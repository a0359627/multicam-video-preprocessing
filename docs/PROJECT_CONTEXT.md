以盛威 fork `a0359627/multicam-video-preprocessing` 的穩定基準 `39bc03b` 開發，開發分支 `codex/multicam-portable-audio`，交接分支為 `feat/gemini-3.8-test-c-workflow`。本修正以 fast-forward 方式更新交接分支；精確提交與推送狀態以 Git 記錄為準。預設 `main` 未更新。

- 已實作 optional `--master-audio` 聲學對齊、同步結果保存、無 OBS 的連續機位混音、通用 XML／MP4 匯出及每工作獨立 GCS 暫存路徑。
- 完整測試 **93 項通過**，包含 8 項實際 FFmpeg／官方 CLI 媒體整合測試。命令：啟用 `.venv` 後執行 `python3 -m unittest discover -s tests -v`。
- 原訪談素材的 **12 秒、無 OBS 前處理**與另一次指定 OBS 的聲學對齊皆成功。兩者各用固定診斷 EDL 經官方腳本產生 XML／MP4；均為 3840×2160、30000/1001 fps、300 格、10.010 秒，影片與音訊長度一致。無 OBS XML 為 4 音軌；有 OBS XML 為 6 音軌。無 OBS MP4 解碼確認非靜音，平均 -18.1 dB、峰值 -1.6 dB。這是媒體管線驗證，診斷 EDL 並非新一輪模型剪輯結果。
- 真實 4K 硬體輸出暴露了每段使用時間長度裁切會累積少格的問題；修正為依 EDL 指定精確影格數。軟體／macOS 硬體整合測試均檢查影格總數。
- 可重現合成音訊測試：無母帶混音與期望訊號相關性 > 0.99；母帶對齊後 > 0.99，且錯誤偏移無法通過。涵蓋 mono／stereo、25／29.97 fps、60 fps MKV 母帶搭配 25 fps 時間軸、非零起點與中間刪段。GCS 隔離／清理以 mock 驗證，未以同事憑證實際上傳。
- 本次沒有進行付費 Gemini 推論，也沒有實際 DaVinci Resolve 匯入／聽驗。未在同事電腦完成安裝或端到端驗收，不宣稱已完成其首支實片。
- 本機驗證環境：Python `3.14.5`、numpy `2.5.3`、google-genai `2.29.0`、google-cloud-storage `3.16.0`、requests `2.34.2`。安裝文件要求 Python >= 3.10，建議 3.11／3.12；Windows 尚未驗證。

## 重要決策

使用者於 2026-10-08 授權先修好再交給同事，並要求沒有 OBS 也可成片。保留 fork 的三階段、全長影片與 Test C 自然節奏，不整包合併上游分段流程。

母帶可選；指定後以聲學量測偏移，低可信度或無法涵蓋所需時間即停止，不能偷偷換成機位聲音。未指定母帶時，grid／MP4 使用連續機位混音，每路 `1/N`；XML 保留可獨立調整的機位聲道。有母帶時預設聽母帶，機位軌保留但關閉。軌數依實際聲道數；雙機皆 stereo 為 4 軌，另加 stereo 母帶為 6 軌。

上傳使用 `raw/<job UUID>/<filename>`，同次執行內重試沿用，新的工作重新上傳。清理只處理本次建立的物件，不刪直接提供的 `gs://` 輸入；既有 raw 2 天／交付物 15 天規則不變。

同事使用既有雲端授權、自行完成 ADC 與 quota project 設定，不執行會變更雲端配置的 `setup.sh`。帳號授權名單與任何憑證不放入本 repo。

## 已確認的交接陷阱

- 歷史 Test C 不只寫死偏移，也寫死人物、逐字稿與素材路徑。正式預設改用 `assets/prompt_c_portable.md`；歷史模板和 benchmark 保留以便比較，不能當安裝入口。
- benchmark 的 `export_c_with_master_audio.py` 已改為正式 XML 匯出器的相容入口。`run_production_cut.py` 等其他歷史工具仍含個案固定路徑，範圍已在該目錄 README 標示。
- 新電腦須用 fork 的指定交接分支。只有 repo 網址或預設 `main`，不足以保證拿到此次修正。
- 每組素材使用新輸出目錄，XML 與其引用媒體一起保留。跨電腦搬移後可能需要重新連結，XML 存在不代表剪輯軟體中可正常播放。
